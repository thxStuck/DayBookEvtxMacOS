## Реестр сущностей

При импорте приложение собирает реестр хостов, пользователей и IP-адресов из всех журналов кейса.
Разделы «Хосты», «Пользователи» и «IP-адреса» показывают его в виде таблиц.

### Откуда берутся сущности

Роль сущности в событии определяется по имени поля (точное совпадение с учётом регистра):

| Поля | Сущность | Роль |
|---|---|---|
| `Computer` (System) | хост | журнал (компьютер, записавший событие) |
| SID из System/Security | пользователь | контекст события |
| `Target*`, `TargetUserSid`, `TargetOutbound*`, `AccountName`/`AccountDomain` | пользователь | цель |
| `Subject*`, `User`, `ParentUser` | пользователь | субъект |
| `WorkstationName`, `Workstation`, `ClientName`, `SourceHostname` | хост | источник |
| `DestinationHostname`, `TargetServerName` | хост | назначение |
| `IpAddress`, `ClientAddress`, `SourceIp`, `SourceAddress`, `Address`, `ClientIP` | IP | источник |
| `DestinationIp`, `DestAddress` | IP | назначение |

Особые случаи: в RDP-событии RCM 1149 `Param1` и `Param2` — пользователь, `Param3` — IP; событие
EventLog 6011 (переименование компьютера) добавляет прежнее имя хоста в его «другие написания».

### Нормализация

- **Хосты.** Ведущие `\\` снимаются; значения `-`, `LOCALHOST`, `LOCAL`, `UNKNOWN`, `N/A` и IP-адреса
  отбрасываются; хвостовой `$` снимается; от полного имени (FQDN) берётся первая метка, имя
  приводится к верхнему регистру. `DC01.corp.local`, `dc01` и `DC01$` — один хост.
- **Пользователи.** Формы `ДОМЕН\имя` и `имя@домен` разбираются. `NAME$` в поле пользователя — это
  учётная запись компьютера: он становится хостом с ролью «уч. запись компьютера». Пользователь
  определяется по SID, если он известен; иначе по `ДОМЕН\имя`. Запись без домена присоединяется к
  единственному варианту с доменом.
- **IP-адреса.** Каноническая форма; префикс `::ffff:` снимается; `127.0.0.0/8`, `::1`, `0.0.0.0`
  и `::` отбрасываются.
- **Встроенные учётные записи** (SYSTEM, LOCAL SERVICE, NETWORK SERVICE, DWM-\*, UMFD-\*, учётки
  NT SERVICE, BUILTIN и т. п.) помечаются шестерёнкой. В разделе «Пользователи» их можно скрыть
  переключателем.

### Таблица и карточка

- Колонки: Имя, другие написания (у пользователей — и SID), первое и последнее появление, число
  событий, роли с числом событий в каждой.
- Поиск по имени, другому написанию или SID.
- Двойной клик — все события сущности. Контекстное меню: «Показать все события», «Показать в
  таймлайне», «Исключить из событий», «Копировать имя», «Копировать SID».
- Карточка справа: время появления, число событий, кнопки «Все события» и «Таймлайн».
- **Связи** — сущности других типов, встречающиеся в тех же событиях (до 150), с числом общих событий
  и периодом. Кнопка «События» у связи показывает события, где встречаются обе сущности.

{: .note-ru }
Переход к событиям из реестра всегда начинает **новый поиск**: прежний запрос, фильтры и интервал
времени сбрасываются и не сужают результат. Прежний запрос остаётся в истории.

В запросах сущности ищутся полями `anyhost`, `anyuser`, `anyip` — во всех ролях и написаниях.

## Сеансы входа

Раздел «Сеансы», вкладка «Входы 4624».

### Как строится сеанс

- Используются события журнала Security: вход — 4624, выход — 4634 или 4647.
- Вход и выход сопоставляются по ключу «хост + загрузка + TargetLogonId». LogonId уникален только в
  пределах одной загрузки системы, поэтому загрузка входит в ключ.
- Концом сеанса считается самое раннее ещё не использованное событие выхода не раньше входа.
- **Загрузки** определяются по событиям Kernel-General 12, EventLog 6005 и Security 4608.
  Отметки ближе 300 секунд друг к другу считаются одной загрузкой. Если у хоста нет ни одной такой
  отметки, все его входы считаются одной загрузкой, и хост указывается в подвале как
  «нет данных о загрузках».
- **Привилегированный сеанс** — есть событие 4672 с тем же SubjectLogonId на том же хосте в той же
  загрузке.

| Колонка | Что показывает |
|---|---|
| Начало, Конец, Длительность | Время входа и выхода; «не закрыт» оранжевым, если выхода нет |
| Пользователь | `ДОМЕН\имя` |
| Тип | Тип входа с названием: 2 интерактивный, 3 сетевой, 10 RDP и т. д. |
| Источник | Рабочая станция и/или IP |
| Привил. | «4672», если сеанс привилегированный |
| Хост, LogonId | |

- Фильтр по типу входа и поиск по пользователю, источнику, хосту и LogonId.
- Выбор строки показывает событие входа в панели деталей. Двойной клик — «События сеанса».
- Контекстное меню: «События сеанса», «События сеанса в таймлайне», «Событие входа (4624)»,
  «Событие выхода».
- События сеанса — это запрос: тот же хост, LogonId в полях `TargetLogonId`, `SubjectLogonId` или
  `LogonId`, время от входа до выхода. Его можно посмотреть и изменить в строке запроса.
- В подвале — правило сопоставления и статистика: сеансов, незакрытых, выходов без входа.

## RDP

Вкладка «RDP» раздела «Сеансы».

- Источник — журнал `Microsoft-Windows-TerminalServices-LocalSessionManager/Operational`, события
  21, 22, 23, 24, 25, 39, 40.
- События связываются в цепочку по компьютеру и номеру сеанса (SessionID). Событие 21 начинает
  цепочку, 23 закрывает. Новая 21 при открытой цепочке закрывает её как незакрытую.
- Колонки: Начало, Конец, Хост, Сеанс, Пользователь, Адрес, Шаги. Шаги — последовательность вида
  «21 вход → 22 оболочка → 24 отключение → 25 переподключение → 23 выход».
- Контекстное меню: «Первое событие цепочки», «События LSM этого сеанса».
- События RCM 1149 и Security 4778/4779 в цепочки не входят; они видны в таблице событий с
  описаниями и участвуют в реестре сущностей. RDP-входы в журнале Security — это сеансы типа 10
  на вкладке «Входы 4624».

## Дерево процессов

Раздел «Процессы», переключатель «Sysmon 1/5» / «Security 4688».

### Sysmon

- События Sysmon 1 (создание процесса) и 5 (завершение).
- Узел — ProcessGuid, родитель — ParentProcessGuid. Связь **точная**: её записал сам Sysmon.
- Если события создания родителя нет, строится синтетический узел из полей ParentImage,
  ParentCommandLine и ParentProcessId (оранжевый значок «?»).
- Повторное событие создания с тем же GUID учитывается в подвале как «повторных GUID».

### Security 4688

- События 4688 (создание) и 4689 (завершение).
- Родитель определяется **эвристически** по PID: процесс с PID, равным полю ProcessId из 4688, на
  том же хосте и в той же загрузке; из подходящих — последний, запущенный не позже потомка и не
  завершившийся до его запуска. PID в шестнадцатеричной и десятичной записи считаются одинаковыми.
- Такая связь помечается значком 🔗 с объяснением: PID переиспользуются, проверяйте по времени.
- Если родитель не найден, создаётся синтетический узел из ParentProcessName и PID.

| PID, Запуск, Завершение | |

- Поиск по образу или командной строке превращает дерево в плоский список (до 5000 строк) с
  колонкой «Предки».
- Выбор узла показывает событие создания в панели деталей.
- Контекстное меню: «Перейти к событию создания», «События этого процесса» (для Sysmon — по
  ProcessGuid, для 4688 — по PID в пределах жизни процесса), то же в таймлайне, «Копировать
  командную строку», «Копировать путь».

  связано по PID, повторных GUID.
