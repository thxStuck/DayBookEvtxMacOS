# Язык запросов DQL
{: .no_toc }

[English version](../en/dql.html)

## Коротко

```
EventID = 4624 and LogonType in (3, 10) and not TargetUserName endswith "$"
| group by TargetUserName, IpAddress
| sort count desc
| limit 50
```

- Запрос пишется в строке над таблицей и выполняется по Return или ⌘↩. Кнопка «Стоп» прерывает
  долгий запрос; новый запрос отменяет предыдущий.
- Запрос работает **вместе** с чипами фильтров и выбранным интервалом времени: сначала применяются
  они, затем запрос.
- Крестик в строке очищает запрос, кнопка «Сбросить всё» (⌘K) — запрос, фильтры и интервал.
- Последние 50 запросов хранятся в истории (кнопка с часами).
- Кнопка «?» открывает краткую подсказку.

## Условия

Условие — это `поле оператор значение`. Условия соединяются словами `and`, `or`, `not` и скобками.

- Приоритет: `not` выше `and`, `and` выше `or`.
- Два условия подряд без связки означают `and`: `EventID = 4624 LogonType = 3` — то же, что
  `EventID = 4624 and LogonType = 3`.
- Ключевые слова пишутся в любом регистре.

### Значения и кавычки

- Без кавычек можно писать значения без пробелов и без символов `( ) , | " ' = ! < > ~`:
  `10.20.30.40`, `S-1-5-18`, `0x17`, `ADMIN$`, `C:\Windows\x.exe`, `*\powershell.exe`, `10.0.0.0/8`.
- Значения с пробелами берутся в двойные или одинарные кавычки.
- Внутри кавычек экранируются только своя кавычка и `\\`. Любой другой `\` остаётся как есть, поэтому
  пути Windows можно вставлять без изменений: `Image = "C:\Windows\System32\cmd.exe"`.
- Имя поля с пробелами или совпадающее с ключевым словом пишется в обратных кавычках:
  `` `Threat Name` contains Trojan ``.

### Регистр

- **Имена полей** — без учёта регистра: `eventid`, `EventID` и `@EventID` равнозначны.
  Если в кейсе есть поле с точно таким написанием, оно выигрывает у одноимённого псевдонима:
  `User` — поле Sysmon, `user` — псевдоним SID пользователя.
- **Значения** сравниваются без учёта регистра. Исключение — оператор `==`.

## Операторы

| Оператор | Что делает |
|---|---|
| `=` | Значение совпадает целиком, без учёта регистра. Если в значении есть `*` или `?`, работает как маска `like` |
| `==` | Совпадает целиком с учётом регистра (с `*` или `?` — маска без учёта регистра) |
| `!=` | Всё, что не `=`, **включая события, где поля нет совсем** |
| `<` `<=` `>` `>=` | Сравнение чисел или времени |
| `between a and b` | Числа или время в диапазоне, обе границы включительно |
| `in (a, b, …)` / `not in (…)` | Одно из значений (до 10 000 значений) |
| `contains` или `~` | Подстрока |
| `not contains` или `!~` | Нет подстроки (включая события без поля) |
| `startswith`, `endswith` | Начало или конец значения |
| `like` | Маска: `*` — любые символы, `?` — один символ; маска охватывает значение целиком |
| `matches` или `regex` | Регулярное выражение |
| `cidr` | Адрес в подсети: `IpAddress cidr 10.0.0.0/8` |
| `exists` / `not exists` | Поле есть / поля нет |

После имени поля `not` допустим только перед `in`, `contains` и `exists`. Для остальных случаев
пишите `not` перед условием: `not Image endswith "\explorer.exe"`.

### Подстроки и маски

- `contains`, `startswith`, `endswith` сравнивают буквально: `*`, `?`, `%`, `_` — обычные символы.
  Пустое значение ничего не находит.
- `like` и `=` с `*`/`?` — маска. Экранировать сами `*` и `?` нельзя.
- Все эти операторы — без учёта регистра.

### Регулярные выражения

- Движок ICU (`NSRegularExpression`), без учёта регистра.
- Ищется вхождение в любом месте значения. Чтобы привязать к началу или концу, используйте `^` и `$`.
- Выражение проверяется на каждом уникальном значении поля, параллельно.
- На одно значение отводится 2 секунды процессорного времени. Значение, на котором выражение
  работает дольше, пропускается. Детекты сообщают об этом предупреждением у правила; строка запроса
  такого предупреждения пока не показывает.

### Подсети

`cidr` принимает IPv4 и IPv6: `адрес/префикс`, без префикса — один адрес. Значения полей вида
`::ffff:10.1.2.3`, `[192.168.1.1]` и `fe80::1%12` распознаются.

## Числа

- `<`, `<=`, `>`, `>=` и `between` работают только с числами: десятичными (можно с минусом) или
  шестнадцатеричными `0x…`. Нечисловые значения в такие выборки не попадают.
- `=` сравнивает **текст**: `TicketEncryptionType = 0x17` найдёт `0x17`, но не `23`;
  `LogonType = 03` не найдёт `3`.

## Время

Поле `time` (также `timestamp`, `timecreated`) — это TimeCreated события, а если его нет — время
записи в журнал.

```
time >= "2026-09-30 10:00" and time < "2026-09-30 12:00"
time between "2026-09-30 10:00" and "2026-09-30 12:00:30.5"
time >= 2026-09-30T07:00Z
```

- Формат: `ГГГГ-ММ-ДД[ ЧЧ:ММ[:СС[.fffffff]]]`, между датой и временем — пробел или `T`.
  Одна дата означает 00:00, доли секунды — до 7 цифр.
- Без суффикса время понимается **в выбранном часовом поясе** отображения.
  Суффикс `Z` — UTC, `+03:00` или `-05:00` — явное смещение (с двоеточием).
- Значение с пробелом берётся в кавычки.
- `time = …` означает «в пределах этой секунды».
- `between` включает обе границы, порядок границ не важен.
- Для поля `time` допустимы `<`, `<=`, `>`, `>=`, `between`, `=`, `!=`. `in`, группировка и
  `exists` по времени не поддерживаются.

{: .note-ru }
Если сменить часовой пояс, уже выполненный запрос не перезапускается: его время было понято в прежнем
поясе. Выполните запрос заново.

Интервал удобнее задавать на гистограмме: выделите область протягиванием и нажмите «Фильтр по
выделению». Интервал появится оранжевым чипом.

## Поиск по всем полям

Строка в кавычках без имени поля ищет подстроку во всех полях события, включая системные:

```
"mimikatz"
"mimikatz" "sekurlsa"            — обе подстроки (неявный and)
EventID = 4104 | search "Invoke-WebRequest"
```

Это поиск подстроки без учёта регистра, а не поиск по словам. Слово без кавычек считается именем поля.

## Сравнение двух полей

Правая часть в обратных кавычках — это другое поле:

```
Image endswith `OriginalFileName`
TargetUserName != `SubjectUserName`
```

- Операторы: `=`, `==`, `!=`, `contains`/`~`, `startswith`, `endswith`.
- Берётся первое значение каждого поля, рассматриваются события, где есть оба поля
  (`!=` включает и события без одного из полей).
- Сравниваются поля данных события (EventData/UserData), не системные поля.

## Поля

### Поля данных события

- `<Data Name="X">` даёт поле `X`; безымянный `<Data>` — поле `Data` (может повторяться).
- Для UserData имя — путь ниже корневого элемента через точку, атрибут — `путь.атрибут`.
- Если шаблон записи не найден, поля называются `Value[0]`, `Value[1]`, …
- Неизвестное имя поля даёт ошибку с подсказкой похожих имён.

### Системные поля и псевдонимы

| Пишите | Ключ | Что содержит |
|---|---|---|
| `EventID`, `id`, `event_id` | `@EventID` | Код события десятичным числом (без Qualifiers) |
| `channel`, `log` | `@Channel` | Журнал, например `Security`, `Microsoft-Windows-Sysmon/Operational` |
| `provider`, `provider_name` | `@Provider` | Источник (Provider Name) |
| `host`, `computer` | `@Computer` | Поле Computer как записано в событии |
| `level` | `@Level` | Уровень: число или слово (см. ниже) |
| `user`, `userid`, `sid` | `@UserID` | SID из System/Security |
| `file`, `source` | `@Source` | Имя исходного файла (при совпадении имён — с папками) |
| `flag`, `flags` | `@Flag` | Флаги записи, см. [Кейсы и импорт](cases-import.html#флаги-записей) |
| `task`, `opcode` | `@Task`, `@Opcode` | Числа из System |
| `keywords` | `@Keywords` | 16 шестнадцатеричных цифр: `0x8020000000000000` |

Уровень можно писать числом или словом в операторах `=`, `!=`, `in`: `critical`/`критический` = 1,
`error`/`ошибка` = 2, `warning`/`предупреждение` = 3, `information`/`info`/`сведения` = 4 (включает
и 0), `verbose`/`подробно` = 5.

Аудит в журнале Security задаётся через `keywords`: успех — `0x8020000000000000`,
отказ — `0x8010000000000000`.

{: .warning-ru }
Номер записи (EventRecordID), ProcessID и ThreadID хранятся в кейсе и показываются в деталях, но в
запросах пока недоступны.

### Сущности, закладки и детекты

| Поле | Операторы | Что ищет |
|---|---|---|
| `anyhost`, `anyuser`, `anyip` | `=`, `!=`, `in` | События сущности во всех ролях: хост в любом написании, IP в любой форме, пользователя по имени, `ДОМЕН\имя`, `имя@домен` или SID |
| `tag` (`bookmark`) | `=`, `!=`, `in`, `exists` | Закладки по цвету: `red`, `orange`, `yellow`, `green`, `blue`, `purple`; `tag = *` — любая |
| `rule` | `=`, `!=`, `in`, `contains`, `exists` | События, на которых сработало правило: по id или названию; `rule exists` — любое |
| `rulelevel` | `=`, `!=`, `in`, `<`, `>`… | По уровню сработавших правил: `informational`, `low`, `medium`, `high`, `critical` |

Примеры: `anyip = 10.20.30.40`, `anyuser = "CORP\j.doe"`, `tag = red`, `rulelevel >= high`.

## Конвейер

После условий через `|` идут стадии. `|` перед ключевым словом стадии можно не писать; запрос может
начинаться сразу со стадии: `| group by IpAddress`.

| Стадия | Что делает |
|---|---|
| `where <условие>` | Добавляет условие через `and`. Можно повторять |
| `search "строка"` | Добавляет поиск подстроки по всем полям |
| `select f1, f2` (`project`) | Задаёт колонки таблицы: время всегда первое, затем указанные поля, в конце — описание. Отбор событий не меняет |
| `group by f1, f2` | Группы со счётчиками. По умолчанию — по убыванию числа событий. Событие без поля попадает в группу «—». Не больше 20 000 групп |
| `sort f [asc\|desc]` (`order by`) | Сортировка. Учитывается **первый** ключ |
| `limit n` (`take`) | Первые n строк или групп |

### Сортировка

- `sort time desc` / `sort time` — новые сверху / старые сверху. Без `sort time` таблица сохраняет
  текущий порядок.
- По другому полю: числа сравниваются как числа, текст — «естественно» (`file2` < `file10`).
  Внутри равных значений — по времени; события без поля — в конце.
- С `group by`: `sort count` — по возрастанию, `sort count desc` — по убыванию (по умолчанию),
  `sort <поле группировки>` — по значению.

### Limit

- Без сортировки `limit n` даёт **n самых ранних** событий; с `sort time desc` — n самых новых.
- Гистограмма строится по результату до `sort` и `limit`.

### Группы

Клик по группе показывает её события. Двойной клик или «Превратить в фильтры и показать события»
превращает значения группы в чипы фильтров и убирает стадию `group by`.

## Ограничения

| Что | Предел |
|---|---|
| Длина запроса | 199 999 токенов |
| Вложенность скобок | около 62 уровней |
| Список `in` | 10 000 значений |
| Регулярное выражение | 2 с процессорного времени на одно значение |
| Группы | 20 000 |
| История запросов | 50 (в меню видны 25) |

Общего тайм-аута у запроса нет: долгий запрос останавливается кнопкой «Стоп».

## Ошибки

Ошибка показывается под строкой запроса с позицией символа:

| Запрос | Сообщение |
|---|---|
| `EventID = "4624` | Незакрытая кавычка (позиция 11) |
| `(EventID = 1` | Ожидалась «)» (позиция 13) |
| `EventID =` | Ожидалось значение |
| `EventID = 4624 foo` | После «foo» ожидается оператор (=, !=, <, >, contains, in, …) |
| `EventID = 1 \| limit x` | После limit ожидается число |
| `Foo = 1` | Неизвестное поле «Foo» и подсказка похожих имён |

## Как выполняется запрос

- При импорте каждая уникальная строка — значение или имя поля — один раз попадает в словарь.
  События получают номера в порядке времени. Для каждой пары «поле = значение» хранится
  отсортированный список номеров событий — posting-лист. Системные свойства хранятся так же,
  как поля `@EventID`, `@Channel` и т. д.
- Запрос разбирается в дерево и **никогда не превращается в SQL**: ваш текст передаётся в
  фиксированные запросы к словарю только как параметр. Попытка SQL-инъекции в значении просто
  ничего не найдёт.
- Каждое условие находит подходящие значения словаря: хеш для `=`, триграммный полнотекстовый
  индекс для подстрок, числовой индекс для `<` и `>`, перебор для регулярных выражений и подсетей.
  Затем объединяются их posting-листы.
- `and`, `or` и `not` выполняются как пересечение, объединение и разность отсортированных множеств.
  Отрицание не материализует все события. Условия по времени — двоичный поиск по массиву меток
  времени.

## Готовые запросы

Пресеты в боковой панели раздела «События». Их можно открыть, изменить и выполнить.

**Входы и учётные записи**

```
EventID = 4624 | group by LogonType, TargetUserName
EventID = 4625 | group by TargetUserName, IpAddress, SubStatus
EventID = 4625 | group by IpAddress | sort count desc
EventID = 4624 and LogonType = 3 and not TargetUserName endswith "$" | group by IpAddress, TargetUserName
EventID = 4624 and LogonType in (10, 7) | group by IpAddress, TargetUserName
EventID = 4648 | group by SubjectUserName, TargetUserName, TargetServerName
EventID = 4672 and not SubjectUserName in (SYSTEM, "LOCAL SERVICE", "NETWORK SERVICE") and not SubjectUserName endswith "$"
EventID in (4720, 4722, 4724, 4725, 4726, 4728, 4732, 4756, 4738) | group by EventID, TargetUserName
```

**Kerberos и NTLM**

```
EventID = 4769 and TicketEncryptionType = 0x17 and not ServiceName endswith "$"
EventID = 4768 and PreAuthType = 0
EventID = 4776 | group by TargetUserName, Workstation
```

**Выполнение и закрепление**

```
EventID = 4688 or (provider = "Microsoft-Windows-Sysmon" and EventID = 1)
(EventID = 7045 and channel = System) or EventID = 4697
EventID = 4698 or (channel = "Microsoft-Windows-TaskScheduler/Operational" and EventID = 106)
EventID = 4104 and (ScriptBlockText contains FromBase64String or ScriptBlockText contains "Invoke-Expression" or ScriptBlockText contains DownloadString or ScriptBlockText contains "-enc" or ScriptBlockText contains IEX)
provider = "Microsoft-Windows-Sysmon" and EventID = 3 | group by Image, DestinationIp, DestinationPort
provider = "Microsoft-Windows-Sysmon" and EventID = 13 and TargetObject contains "\CurrentVersion\Run"
```

**Сокрытие следов**

```
(EventID = 1102 and channel = Security) or (EventID = 104 and channel = System) or (EventID = 1100 and channel = Security)
EventID = 4616 or (provider = "Microsoft-Windows-Kernel-General" and EventID = 1)
provider = "Microsoft-Windows-Windows Defender" and EventID in (1116, 1117, 5001, 5007)
```

**Доступ к ресурсам и особенности журналов**

```
EventID in (5140, 5145) and ShareName in ("\\\\*\\ADMIN$", "\\\\*\\C$", "\\\\*\\IPC$") | group by IpAddress, ShareName, SubjectUserName
flag = carved
flag = beyondHeader and not flag = stale
flag = timeSkew
flag = parseError
```
